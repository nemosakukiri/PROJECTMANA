## AI会議室（council.html）の動作確認

- 麻奈さんに実際のブラウザで `council.html` を開いてテストしてもらった。
- Claude側：正常に動作。JSON形式で問題認識・懸念点・推奨案・詳細が返ってきた。
- GPT側：エラー。Vercelのランタイムログで原因を確認したところ、
  ```
  OpenAI API error: 429
  "You have no credits remaining."
  "code": "credit_balance_exhausted"
  ```
  → OpenAIのAPIキー自体は設定済みだが、支払い（クレジット）が未設定のため。
- 対応：$5（約700〜750円）のチャージが必要な旨を伝えた。

## 重要：金銭的な制約について（次セッションへの申し送り）

**麻奈さんから「今お金ないねん本当に」と明確に伝えられた。**

- OpenAIのクレジットチャージ（$5程度）を含め、**お金がかかる提案は今後こちらから積極的に持ち出さない**。
- 「覚えておいて」と明示的に依頼された — これは感情表現ではなく、今後のセッションでの制約として扱うこと。
- AI会議室のGPT側は、Claude側の意見表示だけで運用を継続する。GPT側はエラー表示のまま放置してよい（アプリとしては壊れていない、動作として正常）。
- 麻奈さんの側からお金の余裕ができた旨の申し出があるまで、チャージや有料機能の追加を提案しない。
- これはFilovita本体（家計相談アプリ）が扱う「お金がない状態への配慮」と同じ態度を、開発側とのやりとりでも徹底するという話でもある。

## Butlerとの出会い（初回聞き取り）を実装

麻奈さんとの設計対話の流れ：
1. 「バトラーは必ず質問を最初にした方がいい。何も知らないのにマネジメント
   はできない」
2. チャッピーとの対話を引いて「一発話一目的」の原則
3. 「私が昨日された質問攻めのようなものが必要では」→ 既存の「はじめて
   ガイド」（GuideTourScreen）が設定メニューからしか開けず、初回起動時
   にButlerが自動で迎える場面がまだ無いことが判明
4. 「初めましてと質問をしていくのはバトラーの仕事」「いらっしゃいませは
   機能じゃない、役割」→ 設定ウィザードではなく、Butler自身が迎える一続き
   の会話として作り直す
5. 「主に何を使いたいかから質問が分かれていく」「音声で入力する人も念頭に」
6. 「最初にバトラーが生活をマネジメントするということをきちんと提示した
   方がいい」→ 挨拶の中に「管理のお手伝いをします」を明記

実装：`filovita-mvp/src/screens/OnboardingInterviewScreen.jsx`（新規）+
`filovita-mvp/src/components/VoiceTextField.jsx`（新規、1行入力用の
話す/書く両対応部品）。initial launch時、calendarConnectの直後に自動で
始まる。はじめまして→呼び名の交換→「何のお手伝いをしましょうか」→
①買い物・お金／②予定・リズム／③暮らしの種／④まだ分からない、に応じて
一問一答で分岐→お礼。聞いた内容は本物の状態（shoppingBudget /
incomeSchedule / essentialCosts / weeklyLife / nextShoppingDate）に
直接書き込み、答えなかった項目は空のまま（未確認のまま）保持。

詳細な設計意図は `filovita-mvp/docs/LIFE_MODEL.md`「Butlerとの出会い」節。

E2Eテスト（`filovita-mvp/e2e/full-life-journey.spec.mjs`）に、実際の
welcome画面からこの聞き取りを最後まで通し、聞き取った予算・欠かせない
もの（金額未確認のまま）が本物の状態に保存されることを検証するステップを
追加。70ステップ中、失敗0件で完了。ビルドも確認済み。
